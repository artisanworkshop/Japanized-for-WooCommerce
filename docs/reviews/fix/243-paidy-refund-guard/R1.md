## 問題なしと確認した点(サブエージェントの裏取りを含む)
- 入れ子の保存: `status_transition()` は外側の `parent::save()` の後に動き、中の `wc_get_order()` は新しいインスタンス(状態は cancelled)。`wc_create_refund()` の最後の `save()` では状態遷移が起きない
- ステータス保持のフィルタ: 失敗時・Error 時も `finally` で外れる(テストで has_filter を前後比較)
- 再帰: 全額返金でも refunded に遷移しないので `wc_order_fully_refunded` は動かない
- 在庫: 明細を渡さない返金では `wc_restock_refunded_items()` が何もしない。キャンセル時の在庫戻しは WooCommerce 本体
- Analytics: 返金の行は親注文の cancelled を引き継いで除外され、二重計上にならない
- 二重返金の経路: `WC_Paidy_Endpoint` は返金も状態フックも行わない
- 旧版の自動返金済みの判定: 二重返金になる組み合わせは見つからない(ゲートウェイ返金がある = Paidy がまだ全額返金していない)
- 旧形式で保存された ID(`array( array( 'ref_A' ), 'ref_B' )`、2.7.0〜2.9.0 の `WC_Meta_Data` 入り): 文字列でない要素は落ちるが、Paidy の応答の `refunds[]` は決済の全返金を含むので、そこから補われて欠けない(順序は変わる)
