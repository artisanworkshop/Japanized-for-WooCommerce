## 検証した事実
- ミューテーション（`scripts/mutate-check.sh --only`）: 判定を `$coupon->get_discount()` に戻すと `test_zero_discount_saved_as_decimal_string_is_left_out` だけが失敗する（CAUGHT）。ファイルは復元済み
- `0.0 !== (float) …` は、旧判定で除外していた値（`""` `"0"` `0` `0.0` `-0.0` `null` `false`）をすべて除外し、新たに除外するのは値が 0 か無意味な文字列（`"0.00"` `"-0"` `"00"` `"-"` `"."`）だけ。`"0.001"` などの実際の割引は残る（サブエージェントが `php -r` で確認）
- `wc_format_decimal()` は float 以外の入力の小数点記号を `.` にそろえてから数字・`.`・`-` 以外を削るので、保存値の (float) 変換はロケールに左右されない
- テストは DB から読み直した注文で `'0.00'` が保存されていることを前提として固定している
- 品質チェック: `vendor/bin/phpunit` 269 件 OK。phpcs（テストは `--standard=WordPress`、ゲートウェイは `.phpcs.xml.dist`）とも 0 件
