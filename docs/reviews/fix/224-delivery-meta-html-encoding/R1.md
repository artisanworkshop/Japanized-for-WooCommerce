## 指摘
### [R1-1][High][includes/class-jp4wc-delivery.php:660]
plain-text 分岐で `wp_kses_post()` を `wp_strip_all_tags()` に置き換えたが、`wp_strip_all_tags()` は末尾で `trim()` する（wp-includes/formatting.php:5635）。特殊文字を含まない通常の注文でも、配達情報ブロックを囲む先頭と末尾の `\n\n` が消え、WooCommerce の plain メールで直後に出る `BILLING ADDRESS` が閉じ罫線に密着する（`woocommerce_email_customer_details_fields` でフィールドを足しているサイトでは同一行に連結）。新テストは部分一致しか見ておらず検出できない。
**修正方針:** タグ除去をやめて `$output` をそのまま出力する（全経路で `sanitize_text_field()` 済み、text/plain）。通常注文の plain-text 出力全文を `assertSame` で固定する。

### [R1-2][Medium][includes/class-jp4wc-delivery.php:660]
`sanitize_text_field()` は `<` を `&lt;` にして保存し、`decode_stored_value()` がそれを `<` に戻す。その値を `wp_strip_all_tags()`（内部 `strip_tags()`）に通すと `<` 以降が未終了タグとして末尾まで消える（例: 表示名 `10:00<12:00` → plain-text が `Scheduled Time Zone: 10:00` で途切れ、閉じ罫線も消える）。変更前は `10:00&lt;12:00` と見えるだけで欠落はなかった。
**修正方針:** R1-1 と同じ（plain-text でタグ除去をしない）。`<` を含む値のテストを追加。

### [R1-3][Medium][tests/Unit/test-jp4wc-delivery-meta-encoding.php:356-362, 378-384]
HTML 出力の 2 テストは `html_entity_decode()` 後の比較のため、`esc_html()` を外しても `wp_kses_post()` が `&` を正規化して通ってしまう（`esc_html()` 追加を固定するテストが無い）。
**修正方針:** `$printed` 自体を `AM &amp; PM&#039;s &quot;x&quot;` と `assertSame` する。
