## 新規指摘（R1 修正差分で混入したもの）
Critical / High: なし。

### [R2-L1][Low][includes/class-jp4wc-delivery.php:659-660]
plain-text 出力のコメント「Every value in it went through sanitize_text_field()」は厳密には不正確（`wc4jp-date-format` から `date_i18n()` で作る日付と、保存時フィルターの戻り値は通らない。text/plain なので安全性には影響なし）。
**対応:** 根拠を「plain text なので markup として解釈されない」に置き、「stored values are sanitized on save」に弱めた。新規コードのコメントなので同ラウンドで修正。

### [R2-L2][Low][tests/Unit/test-jp4wc-delivery-meta-encoding.php:372-376]
`<` のテストが `&lt;` を meta に直書きしており、`sanitize_text_field()` が `<` を `&lt;` にする前提を固定していない。
**対応:** `save_delivery_data_to_order()` 経由で保存し、meta が `10:00&lt;12:00` であることも `assertSame`。新規テストなので同ラウンドで修正。

## 確認したが問題なし
- `echo $output` の到達経路: クラシック（sanitize 済み）、管理メタボックス（`wc_clean( sanitize_text_field() )`）。ブロック注文は `has_date_or_time()` の `is_block` で早期 return しこの出力に到達しない。`wc4jp-unspecified-date/time` は `'0'` が falsy で `$meta` に入らず出力されない（既存コード）
- 期待文字列の安定性: 描画時に日付整形なし、ラベルは `__()`（テスト環境 en_US）、`strtoupper()` は ASCII のみ。タイムゾーン非依存
- 品質チェック: `vendor/bin/phpunit --filter JP4WC_Delivery_Meta_Encoding_Test` OK（12 件 44 assertion）、全スイート OK（266 件）、test ファイルの phpcs 指摘なし、本体の phpcs は main と同じ既存 2 件のみ
