## 指摘
### [R1-1][Medium][tests/Unit/test-paidy-checkout-return-notice.php]
全テストが `jp4wc_paidy_is_block_checkout` フィルタで判定結果を与えており、`is_block_checkout()` の実際の判定(`CartCheckoutUtils::is_checkout_block_default()` / `has_block()`)を通るテストが無い。判定が壊れても全テストが通る。
**修正方針:** フィルタを外し、Checkout ブロック・`[woocommerce_checkout]`・classic-shortcode ブロックを本文に持つページをチェックアウトページにしたテストを追加する。

### [R1-2][Medium][tests/Unit/test-paidy-checkout-return-notice.php `@runInSeparateProcess`](サブエージェントは Low。テストの独立性に関わるため引き上げ)
子プロセスは bootstrap を再実行し、WordPress のテスト bootstrap が `install.php` で全テーブルを DROP して作り直す。スイートの途中で共有のテスト DB が作り直される。
**修正方針:** `set_up_before_class()` で `WP_TESTS_SKIP_INSTALL=1` を `putenv()` し(子プロセスは親の環境を継ぐ。PHPUnit の `DefaultPhpProcess` は env 未指定なら null で起動)、`tear_down_after_class()` で戻す。子プロセスのテストで値を assert する。

## 対象外指摘(差分範囲外)
- [R1-X1][Low][class-wc-gateway-paidy.php `paidy_make_order()`] 戻り URL を `wc_get_checkout_url() . '?status=…'` で連結しており、パーマリンクが「基本」(`?page_id=N`)だと `?page_id=N?status=rejected` になり通知が出ない。`add_query_arg()` で組み立てる余地。
- [R1-X2][Low][同上] 支払いリンク(order-pay、カートが空)から払って断られると、チェックアウトに戻った時点で `wc_template_redirect` がカートへリダイレクトし、通知も出ず order-pay にも戻れない。戻り先を `$order->get_checkout_payment_url()` にする検討。

## Low(backlogへ)
- [R1-L1][Low][class-wc-gateway-paidy.php `is_block_checkout()`] 判定は設定上のチェックアウトページで決まる。WC の `is_checkout_block_default()` は slug `checkout` で DB テンプレートを探すが、実際の slug は `page-checkout`(WC 11.2.1 で確認)なので、Site Editor でテンプレートに Checkout ブロックを直接置き、ページ本文はショートコードのままのサイトでは classic と誤判定し、通知がセッションに残る(未検証)。実際の描画で決める案: classic は `woocommerce_before_checkout_form` priority 9、block は `render_block_woocommerce/checkout` から enqueue。
- [R1-L3][Low][test `test_callbacks_are_registered_once_and_not_by_instances`] 登録件数 1 の assert は、static コールバックが `_wp_filter_build_unique_id` で正規化されるため失敗し得ない。回帰を防いでいるのは `method_exists` の false。
