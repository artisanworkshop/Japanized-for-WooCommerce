## 指摘
### [R1-1][Medium][tests/Unit/test-paidy-order-status-hooks.php]
static 化した理由の経路がテストされていない。その経路とは、REST や一括操作のように、WooCommerce が決済方法を読み込んでいないリクエストでステータスが変わる場合。挙動テスト 3 件はどれも、先に `WC()->payment_gateways()` を呼んでいる。また、他の決済の注文では一覧を読み込まないというガード(`'paidy' !==` の早期 return)も守られていない。インスタンス側のメソッドも支払い方法を確かめるので、このガードを消しても `test_other_payment_method_is_not_sent` は通る(ミューテーションで確認)。サブエージェントの L2・L3 は Low だったが、修正の中心にある設計の根拠を固定するテストが無いので、テスト欠落として Medium にした。
**修正方針:** `WC_Payment_Gateways::$_instance` をリフレクションで null に戻し、メールによる読み込みも止める。そのうえで、(a) Paidy の注文をキャンセルすると close が 1 回だけ送られる、(b) 他の決済の注文でステータスが変わっても一覧が作られない、の 2 件のテストを足す。tearDown で元のインスタンスに戻す。テストの補助メソッドの docblock が処理と合っていない件(サブエージェントの L6)も、ここで直す。

### [R1-2][Medium][includes/gateways/paidy/class-wc-gateway-paidy.php:201 / tests/Unit/test-paidy-order-status-hooks.php:260]
`register_order_status_hooks()` の `has_action()` のガードと、それを確かめる `test_order_status_callbacks_are_registered_once` は意味が無い。`WP_Hook::add_filter()` は、同じ優先度の同じコールバックを `_wp_filter_build_unique_id()` のキーで上書きするので、ガードが無くても二重にならない(wp-includes/class-wp-hook.php:91-106)。ガードを外してもテストは通る(サブエージェントのミューテーションで確認)。
**修正方針:** ガードとテストを消す。再登録しても増えない理由は、コメントで 1 行書く。

### [R1-3][Medium][readme.txt:169]
changelog の「日本語訳を直した」は、多くのサイトで効かない。WordPress.org の language pack は同梱の `.mo` より優先され、translate.wordpress.org の stable の訳も同じ誤訳だった(CLAUDE.md の Pitfall と同じ構図)。日本語のサイトには通常 language pack が入るので、配布物の記述が実際の挙動と食い違う。
**修正方針:** 「同梱の(bundled)日本語訳」と書く。translate.wordpress.org の訳の修正は、リポジトリの外の作業として最終報告で案内する。
