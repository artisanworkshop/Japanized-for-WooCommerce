## 指摘
### [R1-1][Medium][src/js/jp4wc/admin/settings/components/SecurityScan.js:573]
「もう一度診断する」も常に `consent: true` を送るため、サーバーの同意確認が画面からは効かない。同意を撤回（削除）した後に、撤回前に開いていた別のタブから押すと、チェックを入れ直さずに同意が記録され送信される。同意文の版を上げた更新の前に開いたタブでも同じ。
**修正方針:** 同意欄から押したときだけ `consent: agreed` を送り、同意済みの欄からは `false` を送って `has_consent()` に判断させる。(サブエージェント M1)

### [R1-2][Medium][includes/class-jp4wc-security-scan.php:670 / SecurityScan.js:586]
401 でトークンとレポートを捨てた後の送り直しが失敗（429・503・通信失敗）すると、エラーだけが返り、再登録の案内が一度も出ない（次の成功時は `stored_token()` が null なので `reregistered` が false）。画面は表示内容を取り直さないので、消えたレポートと「トークンを送ります」の行が残る。テストもレポートが消えたことを確かめていない。
**修正方針:** エラーの data に `reregistered` を入れ、JS は失敗時に状態を取り直して再登録の案内も出す。テストで確かめる。(サブエージェント M2 + 自己レビュー)

### [R1-3][Medium][src/js/jp4wc/admin/settings/components/SecurityScan.js:536-568]
帯のプレビュー（`?bands=1`）の読み込み中や失敗時にも診断ボタンが押せ、画面に出ていない帯の値が送られる（同意画面で全値を示す約束（利用規約 第4条）に反する）。応答の順序も確かめていないので、古い応答が新しい表示を上書きしうる。
**修正方針:** 読み込みに連番を付けて最新だけを反映し、帯の読み込み中はボタンを無効に、失敗したら帯のチェックを外す。(自己レビュー + サブエージェント L4 を Medium に引き上げ)

### [R1-4][Medium][tests/Unit/test-jp4wc-security-scan.php:380]
ABSPATH を送らないことの確認が、引用符付きの JSON 文字列（完全一致の値）を探しているため、パスが値の一部に入っても落ちない。
**修正方針:** スラッシュをエスケープしない JSON の中でパスそのものを探す。(自己レビュー + サブエージェント L10)
