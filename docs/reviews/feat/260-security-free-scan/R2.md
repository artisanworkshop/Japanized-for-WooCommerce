## 指摘
### [R2-1][Medium][src/js/jp4wc/admin/settings/components/SecurityScan.js:556-613]（R1-3 の残り）
`checkedAt` が変わったとき（ローカルチェックの再実行後）と失敗後の取り直しが、帯を経由しない `load(false)` を呼ぶ。帯の読み込み中なら `loadingBands` が true のまま残り（ボタンが理由なく無効のまま）、前回の帯の同意から自動で帯を戻した後なら、帯は true のままプレビューだけ帯なしになり、「送信しません」と表示したまま帯が送られる（R1-3 と同じ症状）。
**修正方針:** 読み込みはすべて `loadBands()` を通し、帯と読み込み中の印を常に最新の要求と一緒に更新する。POST / DELETE の応答は進行中の読み込みを無効にしてから表示する（サブエージェントの参考指摘も同時に解消）。

### [R2-2][Medium][includes/class-jp4wc-security-scan.php:684 / SecurityScan.js:756]
R1-2 の修正で、送り直しが失敗したときにも成功時の「wc.artws.info に登録し直したため…」を出していたが、その時点では登録し直せていない。また `reregistered` は別 URL のトークン（ステージング）の場合にも true で、そのトークンは消していないのにエラー時に案内が出ていた。
**修正方針:** エラーの data には 401 でトークンを捨てたときだけ `registration_reset` を入れ、「次の診断で登録し直します」という別の文言を出す（翻訳を追加）。別 URL の場合を含めてテストする。（サブエージェント R2-L2 を、画面の説明が事実と違うため Medium に引き上げ）
