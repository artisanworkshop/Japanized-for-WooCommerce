## 指摘
### [R2-1][Medium][src/js/jp4wc/admin/settings/components/SecurityScan.js:612]
R1-1 の修正で JS が送る版を `scan.consent_version`（直近の GET が返したサーバーの版）にしたため、画面を開いたまま次の版のプラグインに更新されると、1 回目の 409 の後の catch の `loadBands()` で `scan.consent_version` が新しい版に置き換わり、チェックが入ったままの 2 回目のクリックが旧い文面のまま新しい版への同意として通る（帯を切り替えて GET が走った場合は 1 回目から）。今回の 3.0.0 → 3.0.1 は旧 JS が版を送らないので安全で、次の改定から効く。
**修正方針:** 画面の文面の版を JS の定数 `CONSENT_VERSION`（PHP の定数と同じ値・一緒に上げる）として持ち、それを送る。ビルド済み JS が PHP の `CONSENT_VERSION` を送ることをテストで固定する
**対応:** 修正（`const CONSENT_VERSION = '2026-11'`、`test_settings_screen_sends_the_consent_version`。ビルドの値を `2026-10` に変えると当該テストだけが落ちる: CAUGHT, `--only`）

## 確認して問題がなかった点（独立検証）
- 409 をロックの前に返す: 状態を読まない比較のみ
- 更新途中の新旧混在: API が新・Scan が旧なら余分な引数は無視（旧来の動作）、API が旧・Scan が新なら版が `''` で 409（安全側）
- REST 引数は string 型、エラー時は `err.message` で 409 の訳文（`with_bundled_translation` 経由で同梱 .mo にフォールバック）、再読み込みで新しい JS（asset のハッシュが変わる）
- i18n: .mo の差分は追加・変更の 2 件のみ、PO から再現可、JSON は WP-CLI 形式
