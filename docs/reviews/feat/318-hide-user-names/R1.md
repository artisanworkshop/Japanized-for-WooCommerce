## 指摘
### [R1-1][High][includes/class-jp4wc-security-hardening.php:229]
REST の判定が `isset( $query_vars['rest_route'] )` だが、`rest_api_loaded()` は `empty()` で判定する（rest-api.php:449）。`/?author=<ID>x&rest_route=` や `/author/<名前>/?rest_route=` は REST として処理されずに通常の表示に進み、著者アーカイブが 200（body class に nicename）で開く。保護を回避できる（独立レビュー A-1）。
**修正方針:** コアと同じく `! empty( $query_vars['rest_route'] )` で判定し、空や `0` の `rest_route` で 404 になるテストを足す。

### [R1-2][Medium][includes/class-jp4wc-security-hardening.php:388-393]
wp-login.php の判定が「動いているフックが `lostpassword_post` だけ」なので、`wp_loaded` の中で wp-login.php を読み込むプラグイン（WPS Hide Login: `$pagenow` を wp-login.php にして `wp_loaded` から require）では、未登録ユーザーのリセットにコアの「アカウントがありません」が出る（独立レビュー A-2）。
**修正方針:** wp-login.php の処理中であることを `did_action( 'login_form_lostpassword' | 'login_form_retrievepassword' )` と `$pagenow` で判定する。

### [R1-3][Medium][includes/class-jp4wc-security-hardening.php:104-105]
コアは `lostpassword_post` の後に `lostpassword_errors`（5.5）を適用する。ここで拒否する CAPTCHA などは、`lostpassword_post` の最後で exit すると未登録ユーザーにだけ効かず、「送信済み」と CAPTCHA のエラーで名前の有無が分かる（独立レビュー A-3）。
**修正方針:** wp-login.php の経路は `lostpassword_errors` の最後で判定する。WooCommerce はこのフィルターを適用しないので、WooCommerce のフォームだけ `lostpassword_post` で判定する。

### [R1-4][Medium][includes/class-jp4wc-security-hardening.php:381]
`@` を含む未登録の入力ではコアが先に `invalid_email` を足すので、別のプラグインのエラーと重なると「アカウントがありません」とそのエラーの 2 つが出る。登録済みならエラーは 1 つで、メールアドレスの有無が分かる（独立レビュー A-4）。
**修正方針:** ユーザーが見つからず別のエラーがあるときは `invalid_email` を外してから返す。
