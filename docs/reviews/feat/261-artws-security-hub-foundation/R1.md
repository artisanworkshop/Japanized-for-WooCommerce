## 指摘
### [R1-1][Medium][tests/fixtures/security-feed/README.md:17-19]
前方互換の取り決めが「書く側」だけ。読む側が未知の項目・未知の enum 値をどう扱うか、POST /scan の v1 を受け付け続けることが書かれていない。配布済みの JP4WC は更新を強制できないので、#257/#260 が Schema どおり厳しく検査すると、後方互換のはずの項目追加で壊れる。
**修正方針:** 読む側は未知の項目を無視し未知の enum 値の要素を読み飛ばす、enum への値の追加は互換を壊す変更、v2 は新しい URL・名前空間で並行運用、を追記。

### [R1-2][Medium][tests/fixtures/security-feed/README.md:32 / schema/vuln-file.schema.json]
Wordfence V3 から契約への変換規則が無い。V3 の `published` は文字列のまま(形式未確認)、`references` は空のことがあるのに `reference` は必須、`reference` は V3 の項目名ではないのに「項目名は V3 に合わせる」と書いている。#262 は「不正データなら前回の生成物を残して stale」なので、Schema に合わないレコードが 1 件あるだけでフィード全体の更新が止まる。
**修正方針:** README に S1 の変換規則(`published` を UTC の ISO 8601 へ、`reference` は id から組み立て、レコード単位で検査して外れたものは除外・記録、stale はフィード全体の失敗時だけ)を書く。

### [R1-3][Medium][tests/fixtures/security-feed/schema/scan-request.schema.json:71-76, 132-138]
`software[].version`(と各 `*_ver`)のパターン `[0-9A-Za-z.+_-]` に合わない Version ヘッダーが実在する(例 `1.0 beta`)。合わない時の送り方が無く、S2 が Schema で弾けば診断全体が 400 になる。
**修正方針:** パターンを「制御文字を含まない」に緩め、64 文字を超える値は空文字で送る(照合しない)と README に定める。

### [R1-4][Medium][plugins/artws-security-hub/tests/Unit/test-contract-schemas.php]
テストの無い制約がある(サブエージェントが制約を消しても 51 件すべて通ることを実測): report の V- / D- / M- と requirement の対応(A- だけテストあり)、10 個のオブジェクトの `additionalProperties: false`、scan-request の version・locale のパターン、local_findings の maxItems、score の minimum。
**修正方針:** 変異ケースを足し、全 Schema をたどって `properties` を持つオブジェクトに `additionalProperties: false` があることを確かめる構造テストを足す。

### [R1-5][Medium][package.json:30,35]
`make-pot` と `i18n:pot` はリポジトリ全体を走査し(`make-pot` は `--ignore-domain`)、`plugins/` を除外していない。S1/S2 が `artws-security-hub` の文字列を足すと JP4WC の POT(配布物)に混ざる。WP-CLI の `--exclude` は既定の除外(`tests` など)に追加される(`MakePotCommand.php` で確認)。
**修正方針:** 両方の `--exclude` に `plugins/` を足す。

### [R1-6][Medium][tests/fixtures/security-feed/README.md:33-35]
インストール済みのバージョンが空(`software[].version` は空を許す)の時の照合規則が無い。`version_compare( '', 'x' )` は -1 なので、`from_version: "*"` の範囲で必ず「影響あり」の誤検知になる。
**修正方針:** 「バージョンが空のソフトウェアは照合しない」を README に追記。
