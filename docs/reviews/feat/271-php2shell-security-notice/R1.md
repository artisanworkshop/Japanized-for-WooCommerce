## 指摘
### [R1-1][Medium][includes/artws-php-security-notice/class-notice.php:339, 488 / tests/Unit/test-jp4wc-php-security-notice.php]
マルチサイトの経路が無検証。CI はシングルサイトだけで、テストは `required_capability()` の戻り値と WordPress の `user_can()` を見ているだけ。`get_view()` / `ajax_dismiss()` が `required_capability( false )` に固定されても落ちない(受け入れ条件「マルチサイトでは特権管理者にだけ出る」の回帰を検出できない)。(サブエージェント)
**修正方針:** 権限確認を `current_user_can_update_php()` の 1 か所にまとめ、`is_multisite()` を渡していること・`get_view()` / `ajax_dismiss()` がそれを使うことをソースでテストする

### [R1-2][Medium][includes/artws-php-security-notice/class-notice.php:465, 553]
「今後表示しない」の送信先が絶対 URL の `admin_url( 'admin-ajax.php' )`。管理画面を siteurl と別のホスト(www の有無、プロキシ、http/https)で開いているとクッキーが送られず保存されない。画面上は閉じるので、毎画面モーダルが出続けて止められない。core の `ajaxurl` は `'relative'`。(サブエージェントは Low、実害の大きさから Medium に再判定)
**修正方針:** `admin_url( 'admin-ajax.php', 'relative' )` にし、閉じた直後の画面遷移で送信が切れないよう `fetch` に `keepalive: true` を付ける

## Low(backlogへ)
- [R1-L1][Low][includes/artws-php-security-notice/] 共有ディレクトリの PHP 7.0 互換を自動で守っていない(`.phpcs.xml.dist` は `testVersion 8.1-`、CI は phpcs を走らせない)。今のコードは PHPCompatibilityWP `7.0-` で指摘なし。守るなら `composer lint` に `phpcs --standard=PHPCompatibilityWP --runtime-set testVersion 7.0- includes/artws-php-security-notice/` を足す(composer.json の変更なので人間が判断)。サブエージェントは Medium、CI で強制できず現状は互換のため Low に再判定
- [R1-L2][Low][includes/artws-php-security-notice/register.php] ローダー(`newest()` / `load()`)と `Notice::boot( $callback )` の呼び方は最初に読まれたコピーのものが使われるので、互換を保つ必要があることが docblock に無い。最新版の `class_file` が読めない瞬間は古いコピーがあっても出ない
- [R1-L3][Low][woocommerce-for-japan.php] 同梱 .mo による補完は JP4WC の callback にしか無い。同じ版なら先に登録したプラグイン(フォルダ名順で paidy-wc が先)の callback が使われるので、同梱先にも同じ補完が要る(決済プラグインへの同梱時に対応)
- [R1-L4][Low][woocommerce-for-japan.php:34] 登録する版数をメインファイルに直書き。JP4WC はテストで `Notice::VERSION` との一致を確かめるが、他プラグインで書き換え忘れると古い一覧のコピーが勝ちうる(`version.php` を返す形などを検討)
- [R1-L5][Low][woocommerce-for-japan.php `jp4wc_php_security_notice_bundled_translation()`] `static $files` が読めなかったときの `false` も覚えるので、常駐ワーカーでは再起動まで補完が効かない
- [R1-L6][Low][includes/artws-php-security-notice/class-notice.php `ENDING_BRANCHES` / 文言 `support_ending`] 文言に「PHP 8.2」が固定で入っている。将来 `ENDING_BRANCHES` に 8.3 を足すと 8.3 のサイトに 8.2 の文言が出る(ブランチ名を placeholder で渡す)
- [R1-L7][Low][.phpcs.xml.dist] `artws_` をプラグイン全体の接頭辞として許可しているので、共有ディレクトリ以外で使っても lint が見逃す
- [R1-L8][Low][includes/artws-php-security-notice/class-notice.php CSS] ダイアログの幅によって CVE 番号がハイフンで折り返す(`CVE-2026-` / `109618`)。表示上の問題のみ(wp-env で確認)
- [R1-L9][Low][uninstall.php] user meta `artws_php_security_notice_dismissed` はアンインストールで消さない。キーは同梱プラグインで共有しているため意図的(消すと他プラグインの dismiss も戻る)
