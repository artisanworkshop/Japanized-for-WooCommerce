## 指摘
### [R1-1][Medium][includes/class-jp4wc-security-probe.php:`request()`]
自サーバーからの要求そのものが手前で止められる構成（Cloudflare の challenge 403、HEAD を 405 で拒否するサーバー、429）では、A-02・A-04・A-05・D-01・D-04 がまとめて偽の pass（405 なら A-04 だけ偽の fail）になる。
**修正方針:** 実行ごとに最初の要求の前にトップページへ HEAD を 1 回送り、401/403/405/429/5xx なら自己 HTTP の結果をすべて unknown にする。

### [R1-2][Medium][includes/class-jp4wc-security-checks.php:`htaccess_restricts_login()`]
`wp-admin/.htaccess` がブロック単位で見られておらず、`<Files install.php> Deny from all </Files>` だけで A-02 が pass になる。ルートの `<Files wp-login.php>` も `Allow from` 単独（`Allow from all` = 全許可）で pass になる。
**修正方針:** `wp-admin/.htaccess` は `<Files>` / `<FilesMatch>` ブロックを除いて判定し、`Allow from` を条件から外す。

### [R1-3][Medium][includes/class-jp4wc-security-checks.php:`is_harmless_php()`]
先頭の exit / die / `__halt_compiler` 以外をすべて「コードあり」とするため、プラグインが uploads に置く保護用 index.php（`header( '... 404 Not Found' )` だけ）、`return array(...)` のデータファイル、Twig のコンパイル済みキャッシュ（`use` / `class` で始まる）で M-03（High）が fail する。加盟店はプラグインが作り直すので直せない。
**修正方針:** `header()` / `http_response_code()` をリテラル引数で呼ぶだけの文、リテラルだけを返す `return` を無害とし、宣言（namespace / use / class 等）で始まるファイルは続きを読んでいないので unknown にする。

### [R1-4][Medium][includes/class-jp4wc-security-checks.php:`exposed_files()` / `log_files()`]
D-02 が uploads 直下を件数上限なしの `scandir()` で読む。年月フォルダーを使わない大規模サイトで直下に数十万件あると、名前の配列だけで数十 MB になり cron が memory_limit に当たる（issue の「件数に上限」も満たさない）。
**修正方針:** `readdir()` で 1 件ずつ読み、M-03 と同じ上限を超えたら unknown。D-04 の `scandir()` も同じ読み方にする。

### [R1-5][Medium][includes/class-jp4wc-security-feed.php:`rescan()` / probe.php:`request()`]
照合結果とチェック結果を 1 回で書くため、チェックが例外を投げると V-01 の照合結果も保存されず、通知の更新が止まる（Phase 1 からの後退）。`pre_http_request` が配列でも WP_Error でもない値を返すと `status_for_code( array )` で TypeError になる。
**修正方針:** 各チェックを `Throwable` で囲んで unknown にし、Probe は配列でない応答を unknown にする。

### [R1-6][Medium][includes/class-jp4wc-security-checks.php:`EXPOSED_FILE_PATTERN`]
`.gz` が公開前提の `sitemap.xml.gz` に一致し、D-02（Critical 25）が偽の fail になる。
**修正方針:** 圧縮ファイルは `.sql.gz` と `.tar.gz` に限る（`.tgz` は既存）。

### [R1-7][Medium][tests/Unit/test-jp4wc-security-checks.php:`test_d02_default_directories` / test-jp4wc-security-feed-sync.php:`written_option_provider`]
`test_d02_default_directories` の最初の assert が fail も許すため、テスト環境の実際の wp-content に `debug.log` などがあると後の 2 つの fail の assert が何も確かめない。`written_option_provider` に probes のオプションが無く、無効化の割り込みで probes が残らないことを確かめていない。
**修正方針:** wp-content もコンテキストで差し替えられるようにして最初を pass と assert し、provider に probes を加えて assert する。
