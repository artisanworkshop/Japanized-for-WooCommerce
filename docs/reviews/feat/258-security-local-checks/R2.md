## 指摘
### [R2-1][High][includes/class-jp4wc-security-checks.php:`is_plain_exit()`]
読み込み（1 KB）の境界で切れたとき、最後の意味のあるトークンが `exit` / `die` だと「続きなし」として無害と判定する。`<?php exit` + 1100 バイトの空白 + `(system($_GET['c']));` は `exit` の引数として system を実行する（サブエージェントが実行して確認）。R1 の修正で `header(...); die` + 埋め草の経路も無害になった。
**修正方針:** `is_plain_exit()` に `$whole` を渡し、続きが読めていなければ null（unknown）。読む量も 64 KB に増やす。

### [R2-2][Medium][checks.php:`is_harmless_php()`（宣言で始まるファイル）]
宣言で始まるファイルを、全体を読めた場合も null にしていた。`function a(){} system(...)`、`namespace X; system(...)` など宣言を先頭に置いた Web シェルが unknown（減点なし）になる（R1 版では fail）。
**修正方針:** 全体を読めたときはトップレベルの文がすべて宣言か調べ（`declares_only()`）、宣言以外があれば false。namespace / declare のブロックは中身が実行されるので false。

### [R2-3][Medium][checks.php:`is_harmless_php()`（切れたトークン）]
ダブルクォートの文字列が切れると `"` と T_ENCAPSED_AND_WHITESPACE の 2 トークンに分かれ、`array_pop` 1 回では `"` が残って大きなデータファイルが fail（High）になる。
**修正方針:** 切れたときは末尾の `"` / `` ` `` / heredoc 開始 / T_ENCAPSED_AND_WHITESPACE も外す（外すほど null 寄りになり、true にはならない）。

### [R2-4][Medium][checks.php:`run_check()` / テスト]
`catch ( Throwable )` が、phpunit.xml が例外に変えた warning も unknown として飲み込むため、`unknown` を期待するテストが壊れたコードでも通りうる（CLAUDE.md の「warning がテストの期待する失敗の身代わりになる」）。本番でも例外が記録されない。
**修正方針:** `jp4wc_security_check_error` アクションを出し、チェック・同期のテストで想定外に呼ばれたら fail にする。
