## 指摘
### [R1-1][Medium][includes/class-jp4wc-security-scan.php `record_consent()` / `stored_consent()`]
ステージングを作るときの URL 置換（`wp search-replace`、WP Migrate、Duplicator、ホスティングのステージング機能）は、シリアライズされた option の中の URL も書き換える。同意に `site_url` を平文で保存すると、置換を伴う複製では本番の同意がステージングでも有効になり、#319 が直らない（テストは置換しない複製しか再現していなかった）。旧形式の同意が参照するトークンの `site_url` も同様に書き換わる。
**修正方針:** ユーザー判断（2026-11-11、AskUserQuestion）で「ハッシュ + 更新時の移行」。同意には `site_hash`（`sha256( site_key( home_url() ) )`）を保存して比較し、URL は保存しない。3.0.x の旧形式の同意は、更新時（`JP4WC_Install::install()` → `JP4WC_Security_Scan::upgrade_consent()`）にロックを取って DB から読み、トークンの URL で今のサイトの同意と分かればハッシュを書き込む。トークンとレポートはこの PR では変えない（X-1 を #329 に追記）。
