## R1-2 の残り（R2 で修正）
範囲の上限が、コードから導ける範囲より緩かった:
- **同数の順序**: 同じ数なら上のマスから隠すので、「—」は同じ表で上にある表示中のマスより真に小さい。例: 売上 20/20/6/5/2/20 では B3 が隠れ、上の B2 = 6 が見えているので B3 = 5、B4 = 2 と決まった
- **隠す契機**: 「—」が付いたこと自体が「隠す前に割り出せた」ことを示すので、候補の値ごとに規則を走らせ直す相手には値が決まる場合が残る（例: B0・B1 が Under 5、B2 が「—」、合計 53 → B0 = B1 = 4。R1 の例 B もこの方法では決まる）。値で隠すかどうかを決める限り原理的に残る

**ユーザー判断（2026-11-13）: 今の規則を残し、同数の順序だけ上限に足して、説明を「表の数と範囲の計算からは割り出せない」まで狭める**（画面を見られるのは DB を読める運営者だけ、2026-11 の同意の帯は一覧に 1 件ずつ出る）。

**対応:** 9407fff — `hidden_cap()`（上にある表示中のマスより小さく、下にあるもの以下。「未送信」は最後のマスなのですべてより小さい）。性質テストのモデルも同じ上限にした（「未送信」はどちらの表で隠したか画面に出ないので、両表の上限の大きい方）。例 C の期待値が変わった（売上の数をすべて残し、注文で O3・O4 を隠す）。例 D（同数の順序）を追加。同数の順序を外す変異で例のテストと性質テストの両方が落ちる。docblock と README に限界と決定を書いた。
