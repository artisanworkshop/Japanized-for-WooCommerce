## 指摘
### [R1-1][Medium][includes/class-artws-sec-feed-updater.php watchdog() / republish_manifest() / mark_stale()]
watchdog と republish はロックを取る前に `get_state()` を読み、ロックの中でもプロセス内の option キャッシュから読む。読んでからロックを取るまでに別の実行が成功すると、republish は古い sha256・`stale:false` の manifest で上書きし、watchdog は成功直後のフィードを stale にして、DB の新しい state を古い state で巻き戻す（サブエージェントが `query` フィルタで割り込ませて再現）。また `mark_stale()` は manifest を書けたかに関係なく state を stale にするので、書けなかった後に watchdog がやり直さない。
**修正方針:** ロックを取ってから option キャッシュを捨てて state を読み直す。watchdog の 48 時間判定もロックの中でやり直す。state の stale は manifest を書けた後に保存する。

### [R1-2][Medium][includes/class-artws-sec-feed-updater.php update()]
一時的な失敗（タイムアウト・5xx・一時的な 401）でもすぐ `stale:true` になり、次の日次イベントまで約 24 時間何も走らない。全クライアントが 1 日「データが古い」と表示し続ける。
**修正方針:** 取得・読み込み・書き込みの失敗では 1 時間後の再試行を single event で積む（連続 3 回まで、成功でリセット）。閾値による失敗（データの拒否）は再試行しても同じなので積まない。

### [R1-3][Medium][tests/Unit/test-feed-updater.php]
壊しても既存テストが通る挙動がある: (a) 書き込み段階の失敗で前回の gz が残ること、(b)「Allow fewer records」のフラグが失敗した実行では消えないこと、(c) 'manual' イベントが accepted_args=0 で呼ばれること（1 にすると `update('manual')` → `$now=0` で 1970 年の version で公開される）、(d) ロック中の EOL 保存の扱い（実行中のプロセスは alloptions キャッシュの古い EOL で manifest を書くので、スキップしたままだと最大 24 時間反映されない）。
**修正方針:** 4 ケースのテストを足す。(d) はロック中にスキップしたとき republish を single event で積む挙動にしてから固定する。

### [R1-4][Medium][includes/class-artws-sec-feed-updater.php unschedule_events()]
プラグインを無効化すると watchdog も止まり、静的な manifest は `stale:false` のまま配信され続ける（issue の「一定時間更新がない場合も stale」が成り立たない）。
**修正方針:** 無効化時に manifest を stale にする。

### [R1-5][Medium][includes/class-artws-sec-feed-updater.php download()]
fatal（メモリ・時間切れ。watchdog が想定している場面）で死んだ実行は、`get_temp_dir()` に落とした数十〜百数十 MB のダウンロードを消さない。`delete_stale_temp_files()` はフィードのディレクトリしか見ないので、fatal が毎日続くとそのたびに溜まる。
**修正方針:** 実行の最初に `get_temp_dir()` の `artws-sec-wordfence-*` のうち 1 時間より古いものも消す。

### [R1-6][Medium][includes/class-artws-sec-record-validator.php:16 ほか / CLAUDE.md:203]
自動整形（phpcbf の CapitalPDangit）がキーと slug の `wordpress` を `WordPress` に書き換え、docblock の array shape・コメント・テストの説明が実際のキーと食い違っている。CLAUDE.md の plugins 共通の説明は CI が実際に走らせる `composer test` と食い違う。
**修正方針:** `wordpress` に戻して phpcs:ignore を付けるか言い回しを変える。CLAUDE.md は「ローカルは test-local、CI は test」と書き分ける。
