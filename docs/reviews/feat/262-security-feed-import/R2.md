## 指摘
### [R1-4][Medium][includes/class-artws-sec-feed-updater.php deactivate()]（R1 から継続）
**修正方針:** 無効化で非 autoload のフラグ option を立て、ロックが取れなくても DB の state から stale の manifest を書く。実行中の取り込みは、成功時に manifest を書く直前にフラグを DB から読み、立っていれば stale で公開する。有効化でフラグを消す。ロック保持中の無効化と、フラグが立った実行のテストを足す。

## 新規指摘（Low、backlog へ）
- [R2-1][Low][includes/class-artws-sec-feed-updater.php run() / class-artws-sec-admin.php] 同じ回数の再試行が予約済みでも status の `retry_at` に `$now + RETRY_DELAY` が入り、画面の予約時刻が実際とずれる。再試行が 'locked' で終わると過去の時刻のまま残る（表示だけ）
- [R2-2][Low][includes/class-artws-sec-feed-updater.php watchdog()] manifest を書けず state を stale にできなかったときも `true` を返し status に 'stale' を記録する（1 時間後にやり直す挙動自体は正しい。戻り値と表示のラベルだけ）
- [R2-3][Low][includes/class-artws-sec-feed-updater.php run()] 取り込みのプロセスは EOL を alloptions のキャッシュから読む。プロセスの起動からロック取得までの間に管理画面で EOL を保存すると、その実行が古い EOL で manifest を書き、次の実行まで（最長 24 時間）戻らない。run() でもロックの中で EOL を DB から読めば防げる
