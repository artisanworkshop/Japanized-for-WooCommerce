## 指摘
### [R1-1][Medium][includes/class-jp4wc-security-scan.php:902-907、tests/fixtures/security-feed/README.md:83]
この変更で、DELETE /site の 401 には 2 つの意味ができた。「登録が無い（削除済み・期限切れ）」と「登録はあるが、発行先と別のサイトなので何も消していない」。クライアントは今までどおり 401 を `remote_deleted: true` として返し、画面は「The check data was deleted from wc.artws.info and from this site.」と出す。契約 README の「401 を『削除済み』として扱ってよい」も、後者には当てはまらない。起きる場面: dev で登録した後、URL 置換で本番に移し、次の診断の前に削除する（ユーザーが許容した移転の場合）。画面は「wc.artws.info から削除した」と言うが、旧登録は 180 日残る。
**修正方針:** クライアントは、サーバーが削除を確かめた 2xx のときだけ `remote_deleted: true` にする。401 は手元のデータを消したうえで false にし、画面は既存の「このサイトのデータを削除した」の文言を出す（新しい文字列は無い）。契約 README の 401 の記述も直す。

### [R1-2][Medium][plugins/artws-security-hub/DEPLOY.md 8 の手順 3]
別のサイトの本文で送る 1 回目の DELETE が 204 だったとき、手順は「前の版が答えている」としか読まない。しかし手順 2 の GET が 401 なら 0.7.0 は動いている。それでも 204 なら、DELETE の本文が PHP まで届いていない（3.2.0 の照合が黙って効かない）。運用者がこの唯一の失敗を見落とし、さらに不要な「テストの登録が消せなかったとき」へ進む。
**修正方針:** 「2 が 401 なのに 3 の 1 回目が 204 なら本文が届いていない。3.2.0 のタグを止めて調べる。2 回目の 401 は登録が消えた結果」と書き添える。
