## 指摘
### [R1-1][Medium][plugins/artws-security-hub/includes/class-artws-sec-rest-controller.php:172]
`GET /scan/{token}` が `get_param( 'token' )` で読むので、クエリ文字列の `?token=` がルートの値を上書きする（CLAUDE.md の get_params の落とし穴）。トークンが合わなければ 401 なので直接の害は無いが、読む値が URL と食い違う。
**修正方針:** `get_url_params()['token']` だけを読み、クエリの `token` を無視するテストを足す。

### [R1-2][Medium][plugins/artws-security-hub/includes/class-artws-sec-rate-limiter.php:122]
IPv4-mapped アドレス（`::ffff:a.b.c.d`）も 16 バイトなので /64 に切り詰められ、すべて `::/64` になる。デュアルスタックで待ち受けるサーバー（nginx `listen [::]:443 ipv6only=off` など）では、全 IPv4 クライアントが 1時間20回を共有する。`ARTWS_SEC_CLIENT_IP_HEADER` のヘッダーが無い要求も、全部 `''` の 1 キーにまとまる。
**修正方針:** mapped アドレスは IPv4 に戻す。指定したヘッダーが無ければ REMOTE_ADDR を使う。テストを足す。

### [R1-3][Medium][plugins/artws-security-hub/includes/class-artws-sec-report-builder.php:305]
V-01 の重大度（減点）がクライアントと違う。クライアントの `JP4WC_Security_Scanner::max_rating()` は rating の無いレコードを None より下に置き、評価済みのものがあればその最大を取る（全部未評価のときだけ medium）。サーバーは未評価を 1 件ごとに medium として最大を取るので、Low + 未評価のサイトで vuln が 92（クライアントは 97）になる。契約 README の「セキュリティタブと同じ計算」に反する。
**修正方針:** クライアントと同じ順位（未評価は最下位）で最大を取る。クライアントの関数と突き合わせるテストを足す。

### [R1-4][Medium][plugins/artws-security-hub/includes/class-artws-sec-vuln-index.php:107 / report-builder.php:266]
インデックスの読み出しが DB エラーで null を返しても、その版の行が丸ごと無くても「レコードなし」として扱い、脆弱なサイトに「要対応の項目は見つかりませんでした」を返す。レート制限はもう消費済み。
**修正方針:** 読み出しエラーと、必ずレコードのある core（`wordpress`）が見つからない場合は例外にして 503 を返す。照合をレート制限の消費より前に行う。

### [R1-5][Medium][plugins/artws-security-hub/includes/class-artws-sec-feed-updater.php:368]
S1 のフィード公開がインデックスの書き込みに依存した。書き込みに失敗すると run 全体が失敗し、全 JP4WC に配る manifest が stale になる（毎日同じ失敗を繰り返しうる）。バッチは「エスケープ前の JSON が 1 MB を超えたら」行を足した後で送るので、大きな slug（core）を含むと 1 文が大きくなる。`Artws_Sec_Db::install()` は dbDelta の成否を見ずに版の option を更新する。
**修正方針:** state に `index_version` を別に持ち、インデックスはフィード公開の後に書く。失敗しても公開は成功のまま status に記録し、診断は前の世代を使い続ける。バッチはエスケープ後の長さで、行を足す前に送る。install は表がそろったときだけ版を記録する。

### [R1-6][Medium][plugins/artws-security-hub/includes/class-artws-sec-rate-limiter.php:74]
同時要求が最後の1回を取り合った時の分岐（影響行数 0）を通るテストが無い（テストの 429 はすべて事前チェックで返る）。また `MYSQLI_CLIENT_FOUND_ROWS` を付けた接続では「変更なし」が 1 を返し、この分岐が働かない。
**修正方針:** 事前チェックの後に行が満杯になる場合のテストを足し、FOUND_ROWS の前提をコメントに書く。

## 対象外指摘（設計・仕様）
- [R1-X1][—][includes/class-artws-sec-rest-controller.php `create_scan()`] `reregister: true` は認証を見ないので、サイトの URL を知る第三者が、そのサイトの診断履歴の削除・トークンの失効・新しいトークンの取得・その時間の枠の消費をできる（429 の `retry_at` から最終診断時刻も分かる）。未登録 URL の先取りも同じ。#263 の仕様が「なりすましで再登録されても過去のレポートは渡らない」として許容している挙動で、この差分のバグではない。塞ぐなら所有確認（サーバーが site_url 側の JP4WC にチャレンジを問い合わせる等）・二段階の再登録・再登録だけ厳しい制限、のいずれかで、仕様の変更になる → ユーザー判断。docblock の「トークン無しで枠を使わせない」は再登録では成り立たないので、R1-4 の修正で書き直す
