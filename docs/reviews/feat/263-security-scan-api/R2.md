## 指摘（R1 の修正で新たに混入したもの）
### [R2-1][Medium][plugins/artws-security-hub/includes/class-artws-sec-rest-controller.php `create_scan()`]
R1-4 で照合をレート制限の消費より前に移したため、枠を使い切った要求でも照合（索引の SELECT 最大 5 回、該当レコードの json_decode と版の比較）が走ってから 429 になる。トークンの要らない経路（未登録 URL・再登録）で、重い処理を上限なく走らせられる。
**修正:** 読むだけの事前チェック `Artws_Sec_Rate_Limiter::blocked_until()`（旧 private の `retry_at()` を公開）を照合の前に置き、枠の消費（`hit()`）は照合の後のまま。`test_rate_limited_request_is_not_matched`（429 のとき索引を一度も引かない）を追加し、事前チェックを外すと落ちることを確認（CAUGHT）

### [R2-2][Medium][plugins/artws-security-hub/includes/class-artws-sec-feed-updater.php `update_index()` / report-builder.php]
R1-5 でインデックスの失敗が run を失敗させなくなったため、書き込みが失敗し続けても feed は stale にならず、診断は古いインデックスで「脆弱性なし」を返し続ける（契約 README の「ほぼ空・古いデータを stale: false で出さない」に反する）。
**修正:** `Artws_Sec_Report_Builder::is_stale()`: フィードが stale のとき、またはインデックスが公開版に追いつかないまま `artws_sec_feed_stale_after`（48 時間。`Artws_Sec_Feed_Updater::stale_after()` に切り出した）を過ぎたとき、データを古いものとして扱う（V-01 は何も見つからなければ unknown、next_steps に stale の案内）。インデックスの時刻は版（`Ymd.His`、UTC）から読む。`test_index_behind_the_feed` を追加し、判定を外すと落ちることを確認（CAUGHT）

R1 の書き直しで、本文の `revenue_band` がクエリの値に負けないことの assert が消えていた。自分の修正で落としたものなので、この回で戻した。
