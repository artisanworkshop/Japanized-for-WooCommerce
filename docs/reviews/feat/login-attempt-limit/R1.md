## 指摘

### [R1-1][High][includes/class-jp4wc-login-limiter.php `record_app_password_failure()`]
`application_password_failed_authentication` は `invalid_username` を含むすべてのエラーで発火し、`wp_validate_application_password`（`determine_current_user` 20）は `PHP_AUTH_USER` を持つ **あらゆる REST リクエスト**で走る（一度でもアプリケーションパスワードが作られたサイト）。Basic 認証で保護したステージングサイトでは、Cart/Checkout ブロックの Store API 呼び出しごとに「失敗」が数えられ、既定の 10 回で全訪問者・全スタッフの IP がロックされる。XML-RPC のパスワード間違いは `authenticate` 20 のアプリケーションパスワード検証でも発火するので二重に数え、拒否済み（`jp4wc_login_locked`）の試行まで数えてロックを延長する。
**修正方針:** このフックを外す。アプリケーションパスワードは 24 文字のランダム値で総当たりの対象にならず、`wp_login_failed` だけで十分。

### [R1-2][High][includes/class-jp4wc-login-limiter.php `protected_by()`]（自分の指摘）
更新中に 3.0.0 の `class-jp4wc-security-checks.php` が先に読まれていると、3.1.0 の limiter が呼ぶ `login_protected_by_other_means()` が無く Fatal（CLAUDE.md の版混在規則）。
**修正方針:** `method_exists()` で確かめ、無ければ `is_active()` は false（不明なら動かない）。

### [R1-3][Medium][includes/class-jp4wc-login-limiter.php `clear()`]
`wp_login` で IP のカウンタも消すが、wp-login.php は GET でも `wp_signon( array() )` を呼び Cookie 認証で `wp_login` が発火する。顧客アカウント（WooCommerce の会員登録）を持つ攻撃者は、9 回失敗 → 自分の Cookie で wp-login.php を GET → IP カウンタが消える、を繰り返せる。IP の上限はパスワードスプレーを抑える唯一の上限なので無効化される。
**修正方針:** `wp_login` ではユーザー名のカウンタだけ消す。IP のカウンタは期限で消える。

### [R1-4][Medium][includes/class-jp4wc-login-limiter.php `user_key()`、SecuritySettings.js の説明文]
`limited` と `limited@example.com` は別のキーなので、ユーザー名ごとの上限が 2 倍になる。説明文「メールアドレスでログインした場合も、そのユーザー名と同じ名前として数えます」は事実と違う。テストはメールの大文字小文字しか混ぜていない。
**修正方針:** `is_email()` なら `get_user_by( 'email' )` で `user_login` に解決する（コアも `wp_authenticate_email_password` で同じ検索をするので列挙の経路は増えない）。テストでログイン名とメールを混ぜる。

### [R1-5][Medium][includes/class-jp4wc-login-limiter.php `increment()`]
transient の read-modify-write なので、並列の試行 N 件が 1〜2 件にしか数えられない（CLAUDE.md が option の RMW として挙げている問題）。
**修正方針:** 失敗 1 件 = options テーブルの 1 行（`jp4wc_login_fail_<type>_<hash>_<id>`、値は期限の時刻）にし、INSERT と COUNT で数える（CLAUDE.md の「キーごとに 1 行」の形）。ロック中 = 期限内の行が上限以上。`$wpdb->last_error` を確かめ、読めないときは通す（可用性優先）が警告をログに残す。

### [R1-6][Medium][includes/class-jp4wc-login-limiter.php `authenticate()` のメッセージ]
ショッパーに見える文字列が `jp4wc_with_bundled_translation()` の中で作られていない。WordPress.org の言語パックが同梱 `.mo` に勝つので、翻訳されるまで日本語サイトでも英語で出る（CLAUDE.md の規則）。
**修正方針:** `function_exists( 'jp4wc_with_bundled_translation' )` のときはその中で組み立てる（版混在の規則どおり関数の有無を見る）。

### [R1-7][Medium][tests/Unit/test-jp4wc-login-limiter.php `tearDown()`]
`unset( $_SERVER['REMOTE_ADDR'] )` がテストライブラリの `127.0.0.1` をプロセスの残りから消す（WC の `WC_Geolocation`、注文の `customer_ip_address` などが影響を受ける）。
**修正方針:** setUp で保存し tearDown で戻す。
