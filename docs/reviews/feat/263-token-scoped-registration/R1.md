## 指摘
### [R1-1][Medium][plugins/artws-security-hub/includes/class-artws-sec-db.php `has_unique_site_key()`]
`$wpdb->get_row( "SHOW INDEX …" )` はクエリ失敗でも null を返す。そのため、最後の確認の `SHOW INDEX` だけが一時的に失敗すると、一意制約が残ったまま版 2 を記録する。以後 `maybe_install()` は走らず、同じ URL の 2 件目の登録が INSERT の重複で毎回 500 になる（案D の要の機能が、手で直すまで止まる）。自己レビューとサブエージェントの両方が検出した。
**修正方針:** `last_error` を見て「判定できない（null）」を返す。DROP は true のときだけ、版の記録は false のときだけ行う。版を記録しないことと、成功時に記録することをテストで固定する。

### [R1-2][Medium][tests/fixtures/security-feed/README.md「形式のバージョン」]
契約は「項目の削除・意味の変更は互換を壊す変更 → `schema_version: 2` / `artws-sec/v2`」と定めている。一方この差分は、v1 のまま `reregister` を削り、トークンなしの POST の意味を変えている。v1 を使うクライアントが未公開であることを前提にした例外が、どこにも書かれていない。
**修正方針:** REST（`artws-sec/v1`）は、それを使う JP4WC（#260）を出すまで v1 のまま直接変える、と 1 行足す。

### [R1-3][Medium][plugins/artws-security-hub/tests/Unit/test-rest-scan.php `test_delete_site`]
この差分で契約に足した「DELETE /site で、同じ `site_url` の他の登録は残る」を確かめるテストが無い（`$other` が別 URL）。「site_key が同じ登録をまとめて消す」退行でも、どのテストも落ちない。
**修正方針:** `$other` を同じ URL で登録する。

## 確認して問題なしとした点（抜粋）
- **認証の分岐**:
  - ヘッダーが無いときだけ新規登録になる。
  - Basic や形式違いは `''` → `find_site_by_token()` が null → 401。
  - URL 不一致は 401 で、枠も使わない。
- **枠のキー**:
  - 新規は新トークンのハッシュ、既存は DB の `token_hash` で、同じ形式。
  - IP の枠は残る。
  - 未登録 URL の推測や、429 の `retry_at` から情報が漏れる経路は無くなった。
- **後片付け**: 保存失敗時の取り消しは新規登録だけ。`reregister` / `restore_token` / `find_site_by_key` の呼び出し元は残っていない（`git grep`）。
- **新規インストール**: 表が無い → false → `KEY site_key` で作成 → 版を記録。
- **DROP INDEX の失敗**: dbDelta の ADD KEY が名前の重複で失敗し、版は記録されない。
- **ミューテーション（実装時に実施）**: 次の 5 件すべて CAUGHT。
  - 枠のキーを URL に戻す
  - URL 不一致を通す
  - DROP INDEX なし
  - 一意制約が残っても版を記録する
  - IP 制限なし
