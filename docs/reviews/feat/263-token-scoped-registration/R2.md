## Low（backlogへ）
- [R2-1][Low][tests/Unit/test-retention.php `test_upgrade_is_not_recorded_when_the_index_cannot_be_read` / class-artws-sec-db.php の DROP 条件] 「DROP は判定が true のときだけ」を固定するテストが無い。
  - 条件を `false !==` に変えると、判定不能のときに通常の索引を DROP し、dbDelta が作り直す。
  - そのときの ALTER がテストの版 '1' を確定させ、assert も通ってしまう。
  - 新しいテストでもクエリを集め、ALTER が 0 件であることを assert する。
- [R2-2][Low][class-artws-sec-db.php `has_unique_site_key()`] `table_exists()` の失敗で null を返す分岐を、どのテストも通っていない（`return false;` に戻しても落ちない）。

## 確認して問題なしとした点
- `install()` の 2 か所の呼び出しは bool|null を正しく扱う（null なら DROP も記録もしない）。
- 新しいテストは DDL を送らないので、版の option は ROLLBACK で戻る。
- `pre_update_option_{option}` は値の一致判定より前に呼ばれるので、記録の呼び出しを数えられる。
- SHOW INDEX が恒久的に失敗する環境では毎回 install が走るが、README に書いた「外せるまで記録しない」と同じ、意図したトレードオフ。
