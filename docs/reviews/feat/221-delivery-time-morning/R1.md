## 指摘
### [R1-1][Medium][includes/jp4wc-common-functions.php]
表示名が空欄の時の既定値を `__( 'Morning' )` でリクエストごとに決めていた。この値はブロックの select の enum も兼ねるので、ページ表示とチェックアウト POST でロケールが違うと（Store API の `_locale=user`、多言語プラグイン）注文が 400 で拒否されうる。
**修正方針:** 既定値を実行時に決めず、保存時に確定させる（R1-2 と同じ修正）。

### [R1-2][Medium][includes/jp4wc-common-functions.php / class-jp4wc-delivery-blocks-integration.php]
既定値「午前中」が英語の「Morning」になる。WordPress.org の言語パック（`wp-content/languages/plugins`）は同梱 `i18n/*.mo` より優先され、リリース直後の言語パックには新しい msgid が無い。加えてブロックのフィールド登録は `woocommerce_init`（init 優先度 0）で、`load_plugin_textdomain()`（init 優先度 1）より前。wp-env（ja、言語パックあり）で実測し、登録された選択肢が `[{"value":"Morning","label":"Morning"}]` だった。
**修正方針:** 管理画面の JS で既定値を入れて保存する（JS 翻訳は同梱 JSON が言語パックより優先される）。トグルを ON にした時点で表示名が空なら「午前中」を入れ（どのタブで保存しても入る。サブエージェントの R1-7）、配送設定タブの保存時にも空なら入れる。同じハンドラで `updateSetting` を 2 回呼べるよう、`Settings.js` の `updateSetting` を関数型の更新にした。

## 対象外指摘（差分範囲外）
- [R1-X1][Medium][WC `CheckoutFieldsAdmin` / `WC_Meta_Box_Order_Data::save`] 管理画面で注文を保存すると、ブロック注文の `_wc_other/jp4wc/delivery-time` が現在の選択肢だけを持つ select として送られる。保存済みの値が今の選択肢に無いと（時間帯の削除、「午前中」の OFF・表示名変更）、注文の保存のたびに先頭の選択肢で上書きされる。既存の挙動で、本機能で起きやすくなる
- [R1-X2][Medium][jp4wc-pro `includes/class-jp4wc-pro-yamato-exporter.php`] ヤマト B2 出力は `wc4jp-delivery-time-zone` を固定の対応表（`'08:00-12:00' => '0812'` など）で変換する。「午前中」は表に無いので Undefined array key の警告が出て時間帯コードが空になる。Pro 側で `jp4wc_get_delivery_time_morning_label()` と一致する値を `0812` に対応させ、`isset` で守る必要がある（別リポジトリ）
- [R1-X3][Low][class-jp4wc.php] ブロック用フィールドの登録（init 優先度 0）が textdomain の読み込み（init 優先度 1）より前。言語パックが無いサイトでは既存のラベルもブロック側だけ英語になる（R1-2 と同じ原因の既存部分）
